# Правила проекта для моделей (Claude, Gemini и другие)

Приложение для инспекторов ДЧС Республики Казахстан: проверка объекта на первичные средства пожаротушения (огнетушители) по Приложению 3 к Правилам пожарной безопасности (приказ МЧС РК № 55) и СТ РК 1487-2006, план этажа по фото, схема со знаками по ГОСТ 12.4.026-2015, отчёт в PDF. Один код для сайта (PWA), Android (Capacitor, native/android) и Windows (Electron, native/desktop). План работ: docs/plan.md.

## Обязательно

1. Приложение работает без сети: ни одного обращения в интернет, все файлы внутри (vendor/). Новый файл приложения добавляется в ASSETS в sw.js.
2. Расчёт меняется только вместе с тестами. Таблицы в js/norms.js сверены с текстом Правил по каждой ячейке: вручную не править.
3. Перед сдачей: `npm test`, `npm run check:ui`, `node tools/check-pwa.js`; после изменения файлов приложения `npm run build` (ставит номер сборки). Распознавание планов проверяется ещё и на наборе: `node tools/vision-gallery.js` (картинки в bench/vision/img, в git их нет).
4. Код без сборщика и без новых зависимостей, пока в docs/plan.md не решено иначе. Без `?.` и `??`: код должен работать в старых Android WebView.
5. Комментарии, названия тестов и сообщения коммитов на русском, коротко и по делу.
6. Тексты интерфейса и документов: docs/style.md. Оформление: docs/design.md. PDF остаётся строгим служебным документом (шрифт Tinos, чёрный текст, цвет только в знаках).
7. Реальные планы объектов, персональные данные и ключи подписи не отправляются во внешние сервисы, в том числе в модели ИИ. Общедоступные планы из bench/vision можно.
8. Ключ подписи APK (%LOCALAPPDATA%\firecalc-build\keys) не трогать и не копировать в репозиторий.

## Работа моделей через agy (Gemini)

Задание лежит файлом в docs/briefs/, общие правила в docs/briefs/common.md. Модель работает в отдельной копии репозитория (git worktree) на своей ветке; результат принимается после проверки diff, тестов и стенда.
