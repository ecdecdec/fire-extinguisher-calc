# ADR 0003: Хранение данных объектов и резервное копирование

## Статус

Принято (23.11.2026).

## Контекст

В версии 1.x все объекты проверки, этажи, помещения, отметки на схеме и изображения планов этажей (в виде строк Data URL / Base64) сохраняются в `localStorage` под ключом `firecalc.store.v2` (а в версии 1.0.1 изображения вынесены в базу IndexedDB `firecalc`, хранилище `img`, но метаданные объектов остаются в `localStorage`).

Ограничения `localStorage`:
- общий предел объёма в браузерах и WebView составляет около 5 МБ;
- запись синхронная и сериализует весь список объектов целиком при каждом сохранении;
- при переполнении или повреждении строки JSON в версии 1.0.0 изменения могли теряться.

Кроме того, инспектору нужно:
- переносить объект с телефона (обход) на рабочий компьютер (оформление отчёта и печать) без интернета и без облака;
- хранить резервную копию всех объектов в файле на случай замены устройства;
- при использовании переносной версии для Windows (`portable.exe`) хранить данные рядом с исполняемым файлом, не оставляя служебные данные в профиле чужого компьютера.

## Решение

1. **Переходный этап (версия 1.0.1 и фаза A версии 2.0)**:
   - сохраняется совместимость с ключом `localStorage` (`firecalc.store.v2`), чтобы уже введённые на пилоте объекты открывались без потери данных;
   - отложенная запись принудительно сбрасывается на диск при сворачивании вкладки или приложения (`visibilitychange`, `pagehide`);
   - при ошибке записи (переполнение хранилища) пользователю выводится постоянное предупреждение;
   - если JSON при чтении повреждён, его исходный текст сохраняется в резервный ключ `firecalc.store.v2.bad`, а не затирается молча;
   - при удалении объекта или этажа связанные изображения планов удаляются из хранилища картинок;
   - переносная сборка для Windows (`Ognetushiteli-*-portable.exe`) перенаправляет `userData` в папку `Огнетушители-данные` рядом с `.exe` (через `PORTABLE_EXECUTABLE_DIR`).
2. **Целевое хранилище версии 2.0 (IndexedDB)**:
   - все объекты и планы этажей переносятся в `IndexedDB` со схемой данных и номером версии схемы (`schemaVersion`);
   - изображения планов хранятся как двоичные `Blob`, без накладных расходов Base64 (экономия около 33 % объёма и памяти);
   - при первом запуске новой версии выполняется автоматический перенос записей из `firecalc.store.v2` в `IndexedDB`;
   - на всех платформах запрашивается `navigator.storage.persist()` и отображается объём занятого места.
3. **Файловый обмен и резервная копия**:
   - отдельный объект сохраняется в файл собственного формата (архив с JSON-данными объекта и изображениями планов этажей) и открывается из файла на другом устройстве;
   - полная резервная копия всех объектов выгружается одним файлом и восстанавливается из него;
   - когда съёмные носители (флешки) запрещены политикой ИБ (п. 131-1 Единых требований), данные объекта и отметки на схеме (без растровых картинок) передаются с экрана телефона на камеру компьютера серией QR-кодов.

## Последствия

- Исчезает ограничение в 5 МБ на список объектов; на устройстве можно хранить десятки объектов с планами нескольких этажей.
- Инспектор не теряет введённые помещения при закрытии окна, сворачивании приложения или обновлении версии.
- Переносная версия на флешке не оставляет следов в профиле Windows на гостевом компьютере.
- Требуется поддерживать код миграции из `localStorage` (`firecalc.store.v2`) в `IndexedDB` и модульные тесты на чтение старого формата данных.
